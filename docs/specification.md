# dentia システム仕様書

歯科専用 AIカルテ下書き生成サービス「**dentia（デンティア）**」の仕様書です。
エンジニアでない方にも分かるよう、平易な説明と技術的な詳細の両方を記載しています。
専門用語は末尾の「**14. 用語集**」で説明しています。

- バージョン: v0.9（ベータ）
- 最終更新: 2026-06
- 想定読者: 経営/企画、歯科医院の導入担当、開発・運用者

---

## 1. システム概要

**dentia は、診療の会話から歯科の「SOAP形式カルテ下書き」を自動生成するWebアプリケーションのＡＩサービスです。**

- 診療を**録音**（または会話テキストを**貼り付け**）するだけで、
- AIが**文字起こし**し、さらに歯科向けに**SOAP形式**へ要約して、
- **S（主訴・問診）/ O（口腔内所見）/ A（評価・診断）/ P（治療計画）** の下書きを作成します。

目的は「**カルテ入力の時間を、患者と向き合う時間に**」。カルテ業務の負担と残業を減らすことを狙いとしています。

> ⚠️ 生成物は「**下書き**」です。最終的な確認・確定は**歯科医師**が行う前提です。

---

## 2. 主な機能

| 機能 | 説明 |
| --- | --- |
| 録音入力 | ブラウザのマイクで診療を録音し、自動で文字起こし → SOAP生成 |
| 手入力 | 会話テキストを貼り付けて生成（録音が使えない時のフォールバック） |
| 歯科SOAP生成 | 歯式・検査・処置を反映した S/O/A/P の下書きを生成 |
| 処置別テンプレート | 初診／再診／メンテナンス(SPT)／補綴／根管治療 で生成内容を最適化 |
| ログイン | メールアドレス＋パスワードでのサインアップ／ログイン |
| カルテ保存 | 生成結果をアカウントに保存し、一覧・閲覧・削除。別端末でも閲覧可 |
| 医院（テナント）単位の共有 | 医院ごとにデータを分離し、同じ医院のメンバーで共有（基盤） |
| 利用制限 | 1分あたり・1日あたりの上限でコスト暴走を抑止 |
| レスポンシブ | PC・タブレット・スマホのブラウザに対応 |

## 5. システム構成（全体図）

```
            ┌─────────────────────────── ブラウザ（PC / スマホ） ───────────────────────────┐
            │  フロントエンド：index.html（React + CSS、1ファイル）                          │
            │   - 録音(MediaRecorder) / 画面表示 / 認証・保存はsupabase-jsで直接              │
            └───────┬───────────────────────────────────┬───────────────────────────────────┘
                    │ ① /api/transcribe（音声）           │ ③ 認証・カルテ保存（直接）
                    │ ② /api/generate（テキスト）          │
                    ▼                                     ▼
   ┌──────────────────────────────────┐      ┌────────────────────────────────────┐
   │  バックエンド：Node.js + Express  │      │  Supabase（認証 + データベース）    │
   │  （server.js / Render上で稼働）    │      │   - Auth（メール＋パスワード）       │
   │   - 静的配信(index.htmlのみ)       │      │   - PostgreSQL + RLS（行レベル保護） │
   │   - 認証ガード/レート制限/日次上限  │◀────▶│   - records / clinics / 他           │
   └───────┬───────────────┬──────────┘      └────────────────────────────────────┘
           │ AI①           │ AI②
           ▼               ▼
 ┌───────────────────┐  ┌───────────────────────┐
 │ OpenAI Whisper     │  │ Anthropic Claude        │
 │ （音声→テキスト）   │  │ （テキスト→歯科SOAP）   │
 │  model: whisper-1  │  │  model: claude-sonnet-4-6│
 └───────────────────┘  └───────────────────────┘
```

- **2段のAI**が連携します：**AI①＝文字起こし（OpenAI Whisper）**、**AI②＝SOAP生成（Anthropic Claude）**。
- **認証・カルテの読み書き**は、ブラウザから Supabase へ直接行い、**RLS（行レベルセキュリティ）**でデータを保護します。
- バックエンドは AI 呼び出しの仲介・認証チェック・利用制限を担当します。

```
  │──────────────▶│  音声をPOST /api/transcribe │                        │            │            │

  │               │                            │◀─── 文字起こしテキスト ─│            │            │
  │               │◀──── { text } ─────────────│（音声はメモリのみ・破棄）│            │            │
  │               │  テキストをPOST /api/generate│                        │            │            │
  │               │───────────────────────────▶│  認証/上限チェック       │            │            │
  │               │                            │──── テキスト＋指示 ─────────────────▶│            │

  │               │◀──── { S,O,A,P } ──────────│                        │            │            │
  │   結果を確認   │  画面に表示＋保存(直接) ──────────────────────────────────────────────────────▶│ records へ保存
```

## 8. データ設計（データベース）

Supabase（PostgreSQL）上のテーブル。すべて **RLS（行レベルセキュリティ）** で「本人／所属医院のみ」アクセス可能に制限。

### records（カルテ）
| 列 | 型 | 説明 |
| --- | --- | --- |
| id | uuid | 主キー |
| user_id | uuid | 作成者（既定 `auth.uid()`） |
| clinic_id | uuid | 所属医院（テナント） |
| created_at | timestamptz | 作成日時 |
| template | text | テンプレ種別（first/recall/spt/pros/endo） |
| transcript | text | 文字起こし／入力テキスト |
| memo | text | 補足メモ（既往歴・アレルギー等） |
| s / o / a / p | text | SOAP各項目 |

### clinics（医院＝テナント）
| id | name | created_at | created_by |

### clinic_members（医院メンバー）
| clinic_id | user_id | role（admin / staff） | created_at |

### api_usage（利用カウンタ）
| user_id | day | count | … 1日あたりの生成回数を記録（上限判定用） |

### アクセス制御（RLS）の考え方
- `records`：**所属医院のメンバー**のみ閲覧・作成・更新・削除可（`clinic_id` 未設定の行は本人のみ＝後方互換）
- `clinics` / `clinic_members`：同じ医院のメンバーのみ参照、管理者(admin)のみ変更
- 補助関数：`is_clinic_member()` / `is_clinic_admin()`（RLS再帰回避）、`ensure_clinic()`（ログイン時に個人医院を自動作成）、`bump_api_usage()`（当日カウント加算）
- 定義は `supabase/schema.sql` / `supabase/usage.sql` / `supabase/multitenant.sql`

## 9. API仕様

バックエンド（`server.js`）が提供するエンドポイント。

### GET `/api/health`
稼働確認。
```json
{ "ok": true, "model": "claude-sonnet-4-6", "transcribeModel": "whisper-1",
  "hasAnthropicKey": true, "hasOpenAIKey": true, "authEnabled": true }
```

### GET `/api/config`
フロントの認証初期化用（Supabaseの公開URL・anonキーを返す。anonキーは公開鍵で、保護はRLS）。
```json
{ "supabaseUrl": "https://xxxx.supabase.co", "supabaseAnonKey": "eyJ..." }
```

### POST `/api/transcribe`（要ログイン）
音声 → 文字起こし。`multipart/form-data` の `audio` に音声ファイル。
- リクエスト: `audio`（webm/mp4 等）＋ ヘッダ `Authorization: Bearer <アクセストークン>`
- レスポンス: `{ "text": "文字起こし結果" }`
- 備考: 音声は**メモリ上でのみ処理し、応答後に破棄**（ディスク保存なし）。上限25MB。

### POST `/api/generate`（要ログイン）
テキスト → 歯科SOAP。
- リクエスト: `{ "conversation": "会話", "memo": "補足(任意)", "template": "first|recall|spt|pros|endo" }`＋ `Authorization` ヘッダ
- レスポンス: `{ "S": "...", "O": "...", "A": "...", "P": "..." }`

### 共通の制限・エラー
- 未ログイン: `401` / 短時間に多すぎ: `429`（1分30回）/ 当日上限超過: `429`（既定200回/日）
- `SUPABASE_*` 未設定の環境では認証チェックを行わず従来動作（ローカル/デモ用の安全網）

## 10. 環境変数

| 変数 | 必須 | 用途 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | ◯ | SOAP生成（Claude） |
| `OPENAI_API_KEY` | ◯ | 文字起こし（Whisper） |
| `SUPABASE_URL` | ◯※ | Supabase プロジェクトURL |
| `SUPABASE_ANON_KEY` | ◯※ | Supabase 公開（anon）キー |
| `ANTHROPIC_MODEL` | 任意 | 既定 `claude-sonnet-4-6` |
| `OPENAI_TRANSCRIBE_MODEL` | 任意 | 既定 `whisper-1` |
| `DAILY_API_LIMIT` | 任意 | 1日あたりの生成上限（既定 200） |
| `PORT` | 任意 | 待受ポート（既定 3000） |

※ `SUPABASE_*` 未設定時はログイン無しの従来モードで動作（カルテ保存は無効）。鍵は `.env` または Render の環境変数で管理し、コードに直書きしない。

## 11. セキュリティとデータの取り扱い

- **認証**：Supabase Auth（メール＋パスワード）。AI系API はログイン必須（サーバーでトークン検証、未ログインは `401`）。
- **データ分離**：Supabase の **RLS** により、本人／所属医院の行のみアクセス可能（他院・他人のデータは見えない）。
- **音声の非保存**：録音音声はサーバーのメモリ上でのみ扱い、文字起こし後に破棄。ディスクに残さない。
- **通信**：HTTPS（Render が終端）。AIのAPIに送ったデータは**学習に使われない設定**。
- **利用制限**：レート制限（1分30回）＋日次上限（既定200回）でコスト暴走・悪用を抑止。
- **配信の最小化**：Webサーバーは `index.html` のみ配信（`server.js`・SQL等は非公開）。
- **セキュリティヘッダ**：`X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` を付与。

## 12. 医療・運用上の方針

- 生成物は「**下書き**」であり、**最終確認は歯科医師**が行う前提（フッターにも明記）。
- **A（評価・診断）は断定を避ける**表現（「〜の可能性」「〜を疑う」「鑑別中」等）。
- 会話に**存在しない所見・検査値は創作しない**（読み取れない項目は無理に埋めない）。
- 入力・生成内容は**診療目的にのみ**利用。共有端末では**ログアウト**を徹底。

## 13. 既知の制約・今後の課題

**制約**
- 歯科専門用語の**文字起こし誤変換**が起こり得る（確認・修正のうえ利用）。
- 録音は **HTTPS または localhost** が必須（ブラウザ仕様）。ブラウザにより録音形式が異なる（Chrome=webm / Safari=mp4 等）。
- 無料ホスティングではアクセスが無いとスリープし、初回起動が遅いことがある。

**今後の課題**（詳細は `docs/commercial-readiness.md`）
- メンバー招待UI、月次/医院単位のコスト上限
- 保存データの暗号化、監査ログ、CSP導入、認証のローカルJWT検証
- 自動テスト(CI)の整備
- 法務：要配慮個人情報の取扱い、患者同意、海外APIへの越境移転、3省2ガイドライン準拠の検討
- レセコン／電子カルテ連携（現在はコピー＆ペースト）

## 14. 用語集

| 用語 | 意味 |
| --- | --- |
| SOAP | 診療記録の基本様式。S=主訴/問診、O=所見、A=評価/診断、P=計画 |
| 歯式 | 歯の位置を表す番号表記（例：#46 = 右下第一大臼歯） |
| EPT | 電気歯髄診。歯の神経の生死を調べる検査 |
| 打診痛 / 冷水痛 | 歯を叩く／冷水でしみる痛みの有無（歯科検査） |
| PD / BOP / PCR | 歯周検査の指標（ポケット深さ／出血／プラーク付着率） |
| SRP / 抜髄 / RCF | 歯石除去（SRP）／神経除去（抜髄）／根管充填（RCF）等の処置 |
| 文字起こし | 音声を文章に変換すること（AI①＝Whisper が担当） |
| SOAP生成 | 会話文から SOAP 形式に要約すること（AI②＝Claude が担当） |
| テナント | 利用組織の単位。ここでは「医院」。医院ごとにデータを分離 |
| RLS | 行レベルセキュリティ。DBで「自分の行だけ見える」を強制する仕組み |
| JWT / アクセストークン | ログイン状態を示す署名付きトークン。API認証に使用 |
| anonキー | Supabaseのクライアント用公開鍵。保護はRLSが担保 |
| レート制限 / 日次上限 | 短時間/1日あたりの呼び出し回数の上限。コスト暴走・悪用の防止 |
| レセコン | レセプトコンピュータ（診療報酬請求の電子化システム） |

こんなお悩みはありませんか？

  • 全顎の所見や歯式（#46 など）の入力に時間がかかる
  • 診療をしながら電子カルテ・レセコンに入力するのが大変
  • 自費カウンセリングの説明内容を、後から正確に記録できない

入力時間の削減

「ながら入力」を減らし、患者さんと向き合う時間を確保。 会話そのものが記録の素材になります。
記録の質の標準化
歯科に最適化したテンプレートで、書き手によるばらつきを抑えた SOAP 下書きを生成します。

02
歯科に特化した設計
🦷dentia

なぜ「歯科版」が必要か

医科の初診は「主訴の一本道」。一方、歯科の初診は
全顎のベースライン記録です。う蝕（C0〜C4）・欠損・補綴物、 歯周基本検査、咬合、エックス線…と、歯式単位で 記録すべき情報が一気に増えます。

汎用の音声カルテでは、この歯科ならではの粒度を うまく構造化できません。dentia は、歯科の語彙と 記録様式に最適化することで、そのまま使える下書きを目指します。

① 歯科の語彙に対応

C0〜C4／EPT／SRP／RCF／BOP／PCR／SPT／歯式 など、歯科特有の用語の文字起こし・整理に対応。

② 全顎ベースラインを構造化

主訴歯だけでなく、全顎のう蝕・欠損・補綴・歯周を歯番ごとに整理。

③ 創作しない

会話・読み上げに無い所見は補わず「未実施／要確認」に。歯式・左右の取り違えを防ぐ設計。
🦷dentia

歯科ならではの深掘り（3 本柱）

歯式単位の構造化

所見を 「#46：所見」 の形式で歯番ごとに整理。欄ごとの転記に強い。

歯周検査の構造化（6点法・PCR%）

読み上げから、歯番ごとに 6点法 PD・BOP・動揺度・PCR% を構造化テキストで出力。

12 の場面別・役割別テンプレ

初診／再診／SPT／補綴／根管／自費カウンセリング／訪問／歯周精密／抜歯外科／小児／矯正／衛生士(SOAPIE)。

07
セキュリティとデータの扱い
🦷dentia

セキュリティとデータの取り扱い

音声は保存しない

文字起こしに使った音声データはサーバーに保存せず、処理後に破棄します。

医院単位のデータ分離

Supabase の Row Level Security（RLS）で、医院ごとに read/write を制限。

アクセス制御・利用上限

API 認証（JWT）・レート制限・1日あたりの利用上限で不正・暴走を抑止。

越境移転の整理

文字起こし／生成は米国の API を利用。学習に使わない設定・DPA 等で整理（プラポリに明記）。

同意の設計

医院＝管理者、dentia＝委託先。患者同意は院内掲示・問診票で医院が取得する設計。

今後の強化（β→正式）

送信前マスキング・監査ログ・3省2ガイドライン準拠を順次整備。
※ 法務・コンプライアンスは専門家レビューを前提に整備中です。本ページは現時点の方針であり、最終的な取扱いは規約・プライバシーポリシーが優先します。

🦷dentia

よくあるご質問

Q1. iPhone で利用できますか？
A1. はい。スマートフォンのブラウザからご利用いただけます。
Q2. 電子カルテ・レセコンと連携できますか？
A2. 現状は項目別コピー／QR転記での貼り付けに対応しています。API 直結はレセコン各社との連携が前提となるため、将来の対応課題です。
Q3. 診断や治療方針を自動で提示しますか？
A3. いいえ。dentia は記録作成の支援に限定し、会話に無い診断名は補いません（医療機器に該当しない想定。専門家確認のうえ整理しています）。
Q4. 歯科の専門用語・固有名詞を追加できますか？
A4. 文字起こしの語彙ヒントの調整に対応しています。医院ごとの用語カスタムは今後の拡張予定です。
